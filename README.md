# Polly's Pop — Production & Inventory Management System

Full-stack inventory and production tracking for a small beverage bottling operation. Tracks pallets of soda from production through warehouse storage to sale.

**Stack:** Python (FastAPI), PostgreSQL, SQLAlchemy (raw SQL), HTML/CSS/JS frontend.

**Users:** Theresa and Cole — both full access (authentication deferred).

## Core inventory flow

1. Pallet created on the production floor
2. System assigns the next global pallet barcode (`00001`, `00002`, …)
3. Label printed via Bluetooth phone app
4. Pallet moved to Warehouse 1 or Warehouse 2 (manual entry in Phase 1)
5. Pallet sold — record written to `sold_products` for analytics export
6. Every state change writes a row to `inventory_movements`

## Phase scope

| Phase | Scope |
|-------|-------|
| **Phase 1 (now)** | Manual input flow — create, move, sell, inventory list, expiring alerts, CSV export. Frontend at `/app`. |
| **Phase 2 (later)** | Scanner gun integration, flavor ordering reminder email (12-week lead time), in-app notifications, analytics API. |

## Database

Seven tables defined in [`backend/db/schema.sql`](backend/db/schema.sql):

| # | Table | Purpose |
|---|-------|---------|
| 1 | `brands` | Reference data (Polly's Pop, Pioneer, Polly-Q) |
| 2 | `products` | Finished goods per brand/flavor; UPC codes stored as reference only |
| 3 | `production_batches` | Batch number format: DDMM + sequence (e.g. `2606111`) |
| 4 | `pallets` | System-generated pallet barcodes |
| 5 | `inventory_movements` | Audit log for every location/state change |
| 6 | `sold_products` | Sales records — feeds Polly's Pop Sales Analytics Dashboard (CSV export) |
| 7 | `notifications` | Expiration alerts (3 months before expiry); flavor-order placeholder (Phase 2) |

**Key business rules** (enforced in SQL constraints and application logic):

- Pallet barcode: global 5-digit sequence (`00001`, `00002`, …) — adjust in `backend/app/services/barcode.py` when final label format is confirmed
- Bottle batch number: `BBxxx` (3-digit sequential, never resets daily)
- Expiration date: entered manually at bottling time
- Storage locations: Production Floor, Warehouse 1, Warehouse 2
- Only pallet-level barcodes are generated by this system
- UPC codes for bottles, 4-packs, and cases are third-party reference data — never generated

**PostgreSQL is required.** `schema.sql` uses PostgreSQL types and constraints (`SERIAL`, `TIMESTAMPTZ`, regex `CHECK`). The connection layer in [`backend/db/connection.py`](backend/db/connection.py) normalizes `DATABASE_URL`, validates connectivity, and reports dialect/status on `/health`.

Reference seed data (brands and flavors) lives in [`backend/db/seed.sql`](backend/db/seed.sql).

## Quick start with Docker

From the project root, start PostgreSQL (matches `backend/.env.example`):

```powershell
docker compose up -d
```

Wait until the database is healthy:

```powershell
docker compose ps
```

Then initialize and run the app:

```powershell
cd backend
copy .env.example .env
$env:PYTHONPATH="."
py db/init_db.py
py -m uvicorn main:app --reload
```

Useful commands:

```powershell
docker compose logs -f db    # view database logs
docker compose stop          # stop PostgreSQL
docker compose down          # stop and remove container (data kept in volume)
docker compose down -v       # stop and delete database volume (full reset)
```

## Backend setup

```powershell
cd backend
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

Edit `.env` and set `DATABASE_URL` to your PostgreSQL instance. Common forms are all accepted:

```env
DATABASE_URL=postgresql+psycopg2://postgres:postgres@localhost:5432/pollyspop
```

Initialize the database (creates tables and loads seed data):

```powershell
$env:PYTHONPATH="."
py db/init_db.py
```

For a clean reset:

```powershell
py db/init_db.py --reset
```

Start the development server:

```powershell
py -m uvicorn main:app --reload
```

- Web app: [http://127.0.0.1:8000/app/](http://127.0.0.1:8000/app/)
- Health check: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health) (includes database status)
- API docs: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

Run tests:

```powershell
py -m pytest tests/ -q
```

## Phase 1 API endpoints

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/health` | App and database health |
| `GET` | `/brands` | List active brands |
| `GET` | `/products?brand_id=` | List products (optionally by brand) |
| `GET` | `/pallets` | List pallets (`location`, `status` filters) |
| `POST` | `/pallets` | Create pallet on Production Floor |
| `GET` | `/pallets/expiring` | Active pallets expiring within 90 days |
| `GET` | `/pallets/{barcode}` | Lookup pallet by barcode |
| `POST` | `/pallets/{barcode}/transfer` | Move to warehouse |
| `POST` | `/pallets/{barcode}/sell` | Mark pallet sold |
| `GET` | `/export/sold-products.csv` | Download sold-product records |
